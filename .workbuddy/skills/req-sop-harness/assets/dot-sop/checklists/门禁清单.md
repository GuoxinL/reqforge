# 门禁检查清单(门禁清单.md)

> 用途:`/sop:gate` 阶段的强制执行清单。逐项检查并记录结果,任一 P0 项不通过即打回。
> 执行方法:AI 逐项执行检查 → 输出"通过/不通过 + 证据"→ 汇总门禁报告。

## 检查项

### 1. 完整性检查
- [ ] 需求目录 `docs/requirements/<日期>-<需求名>/` 存在,01~06 阶段产物文件齐全
- [ ] PRD 全章节存在且非空(1~9 章齐备)
- [ ] 每条功能 FR-xxx 有验收标准 AC-xxx
- [ ] 异常路径已覆盖(非法输入/超时/重试/权限/并发/空数据)
- [ ] Out of Scope 与非目标已列出
- 通过标准:以上全部为"是"

### 2. 可测量性检查
- [ ] 所有目标均有指标:基线值 + 目标值 + 时间窗
- [ ] 每个指标在现有系统中可采集(或已规划埋点,见第 6 章)
- 通过标准:指标不可采集 = 不通过,打回 03

### 3. 一致性检查
- [ ] 术语全文统一(与 `project-context.md` 术语表一致)
- [ ] 与原型、竞品分析、历史 PRD、技术债记录无冲突
- 通过标准:有冲突项必须记录并解决

### 4. 可追溯性检查
- [ ] 每条需求能追溯到来源(state/requirements.md 中的编号/提出人)
- [ ] 关键决策能追溯到 state/decisions.md
- 通过标准:追溯链断裂项必须补齐

### 5. 零歧义测试
- [ ] 随机抽一名未参与撰写的工程师,只看文档能否不问问题直接开发
- [ ] (AI 代理执行时)通读全文,找出任何工程师需要追问才能动手的表述
- 通过标准:0 处歧义;有歧义 → 打回 03 对应章节

### 6. AI 产物抽查(适用于 AI 辅助生成的章节)
- [ ] 无幻觉:不存在的接口、编造的数据、过时的假设
- [ ] 引用文件/链接真实存在
- 通过标准:发现幻觉项必须修正后才能放行

### 7. 视觉规格检查(涉及页面设计的功能)
- [ ] 每个涉及页面设计的 FR 在 MD 中有视觉规格引用,且引用文件(需求目录内)与锚点真实存在
- [ ] 视觉规格文件中颜色/尺寸全部引用设计令牌(:root 变量),无硬编码
- [ ] 视觉规格中的布局/状态与 PRD 功能描述、验收标准一致
- 通过标准:引用断裂或规格冲突 → 打回 03 对应章节

## 门禁结论

- [ ] P0 问题数 = 0
- [ ] P1 问题数 = 0(P1 有处理计划且不影响开工可放行)
- [ ] P2 问题有处理计划与负责人
- 结论:`放行 / 打回(<阶段>)` + 理由

## 打回规则

| 打回目标 | 触发条件 |
|---|---|
| 02 澄清 | 存在未消除的模糊词/冲突需求/未确认假设 |
| 03 结构化 | 章节缺失、验收标准不可测、异常未覆盖、零歧义测试失败、视觉规格引用断裂 |
| 04 评审 | 评审 P0/P1 未清零 |
