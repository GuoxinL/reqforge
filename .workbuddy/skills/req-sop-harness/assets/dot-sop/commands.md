# SOP Harness 命令参考(commands.md)

> 命令为"提示词级"约定,纯文本即可触发(Claude Code / Cursor 可绑定为 slash command)。所有命令均可叠加自然语言输入。

## 场景一:新目录 / 全新需求

```
/sop:new <一句话需求>
```
- 行为:进入 **01 采集**。**创建需求目录** `docs/requirements/<YYYYMMDD>-<需求名>/`,记录需求原文、来源、背景三问(为什么做/解决什么/不做会怎样)、约束,写入目录内 `01-需求采集.md`,并在 `state/requirements.md` 登记索引(记录所在目录)。
- 产出:需求目录 `01-需求采集.md` + 待澄清问题清单。
- 确认点:用户确认需求池记录无误后,进入 `/sop:clarify`。

```
/sop:clarify
```
- 行为:进入 **02 澄清**。AI 逐条追问六要素(用户/场景/成功标准/异常/数据来源/与其他功能关系),MoSCoW 分级,明确非目标,模糊词转数字。
- 产出:需求目录内 `02-需求澄清.md`(澄清记录 + 分级 + 非目标 + 假设)。
- 规则:**追问到置信度 ≥95%**;假设显式记录 `[待确认]` 并指派确认人。
- 确认点:澄清记录与假设清单由用户确认后,进入 `/sop:prd`。

```
/sop:prd
```
- 行为:进入 **03 结构化**。按 `templates/PRD-模板.md` 生成 PRD 主文档,写入需求目录 `03-文档结构化.md`;功能编号 FR-xxx,验收标准 Given-When-Then,写异常路径与 Out of Scope;**涉及页面设计/布局/颜色的功能**,按 `templates/视觉规格-模板.html` 生成视觉规格文件(同目录 `视觉规格-<模块>.html`),并在 MD 对应 FR 下给出锚点引用。
- 产出:需求目录内 `03-文档结构化.md` + (按需)`视觉规格-<模块>.html`。
- 确认点:PRD 初稿由用户过目后,进入 `/sop:review`。

```
/sop:review
```
- 行为:进入 **04 评审**。AI 以研发/测试/设计/运营多角色视角审查,输出意见清单(问题→影响→决定→负责人→时间),写入需求目录 `04-多方评审.md`。
- 确认点:P0/P1 清零、P2 有处理计划后,进入 `/sop:gate`。

```
/sop:gate
```
- 行为:进入 **05 门禁**。执行 `checklists/门禁清单.md` 全部检查项,输出门禁报告,写入需求目录 `05-质量门禁.md`。
- 规则:不通过 → 打回对应阶段并说明原因;通过 → 冻结需求基线。
- 确认点:门禁结论由用户确认。

```
/sop:ship
```
- 行为:进入 **06 交付**。在需求目录生成 `06-交付集成.md`(交付摘要 + 需求-任务-用例映射),更新 `state/decisions.md`、记录变更历史。
- 产出:`06-交付集成.md` + 状态更新。

## 场景二:已有项目(有文档/代码)

```
/sop:init
```
- 行为:
  1. 扫描项目(docs/、README、接口/架构文档、代码模块结构),按 `.sopignore` 排除,**列出扫描范围清单供用户确认**,生成 `state/project-context.md`;
  2. **部署规则引导文件**(分支逻辑,详见 SOP.md §3.5):
     - 项目根存在 `AGENTS.md`(已有项目)→ 末尾**追加**"SOP Harness 引用段"(模板见 SOP.md 附录 A),保留原内容;
     - 不存在(新项目/空目录)→ **新建** `AGENTS.md`(引导内容见附录 A),并创建软连接 `CLAUDE.md → AGENTS.md`、`CODEBUDDY.md → AGENTS.md`(其他工具规则文件按需追加);
  3. 输出**变更清单**(新增文件 / 修改文件 / 软连接),待用户确认。
- 软连接命令:
  - WSL / macOS / Linux:`ln -s AGENTS.md CLAUDE.md`(同理 CODEBUDDY.md)
  - 原生 Windows:`mklink CLAUDE.md AGENTS.md`(需开发者模式或管理员权限)
  - git 仓库需 `core.symlinks=true`
- 时机:每个项目**首次使用执行一次**。

```
/sop:req <一句话需求>
```
- 行为:替代 `/sop:new`。AI 依据 `project-context.md` 定位与该需求相关的文件,引用为上下文,**创建需求目录** `docs/requirements/<YYYYMMDD>-<需求名>/` 并生成简版 `01-需求采集.md`,然后**直接进入 02 澄清**(跳过 01 采集完整流程)。
- 后续阶段命令与场景一相同(`/sop:clarify` → … → `/sop:ship`),产物写入同一需求目录。

## 通用命令

```
/sop:status
```
- 展示:当前阶段、本次需求进度、`state/session.md` 中的待确认项与遗留问题。

```
/sop:help
```
- 展示:本文件命令摘要 + 流程总览。

## 命令行为总则

1. 每个命令执行完,必须输出"产出物摘要 + 待确认项",然后**停下等用户指令**(见 SOP.md §4)。
2. 状态一律持久化到 `.sop/state/`,不得只存在对话里。
3. 用户可用自然语言微调,如 `/sop:prd 去掉埋点章节,我们不做埋点`。
