# 状态层说明(state/README.md)

> Harness 的"记忆"。所有跨会话状态必须持久化到本目录,不得只存在于对话中。
> 全部文件纳入 git 版本管理;`requirements.md` 与 `decisions.md` **追加式维护,禁止覆盖删除历史**。

## 文件清单

| 文件 | 用途 | 维护方式 |
|---|---|---|
| `requirements.md` | 需求池**索引**:全部需求登记(ID/标题/状态/所在目录) | 追加式(新需求追加,历史不删) |
| `decisions.md` | 已拍板的决策记录(ADR 风格) | 追加式 |
| `session.md` | 当前会话进度:进行到哪一阶段、待确认清单 | 每次推进阶段时更新(覆盖式) |
| `project-context.md` | 项目上下文档案:`/sop:init` 产出 | 覆盖式(项目结构变化时更新) |

> 注意:单需求的**完整阶段产物**不存本目录,存于 `docs/requirements/<YYYYMMDD>-<需求名>/`(01~06 阶段文件,见 SOP.md §6);本目录只保存跨需求的索引与决策。

## 模板与字段说明

### requirements.md(需求池)

```markdown
# 需求池(索引)

| ID | 标题 | 来源 | 原始描述(原文) | 优先级候选 | 状态 | 所在目录 |
|---|---|---|---|---|---|---|
| REQ-001 | 企业微信扫码登录 | 业务方-张三-2026-08-14 | "要支持企微扫码登录" | P1 | 澄清中 | docs/requirements/20260814-企业微信扫码登录 |

状态流转:采集 → 澄清中 → 已确认 → 已出 PRD → 已冻结 → 已交付 → 已关闭
说明:完整阶段产物(01~06)见"所在目录",本表只作索引登记。
```

### decisions.md(决策记录)

```markdown
# 决策记录

| 日期 | 决策 | 原因 | 决策人 | 影响范围 |
|---|---|---|---|---|
| 2026-08-14 | 扫码登录与账号密码并存,不替换 | 存量用户迁移成本高 | 王五 | 登录模块 |
```

### session.md(会话进度,覆盖式)

```markdown
# 当前会话

- 活动需求:REQ-001 企业微信扫码登录
- 当前阶段:02 澄清
- 待确认:[ ] 目标用户范围 [ ] 与现有登录关系 [ ] 企微授权范围
- 遗留问题:
- 上次更新时间:
```

### project-context.md(项目上下文档案,由 /sop:init 生成)

```markdown
# 项目上下文

- 项目名 / 定位:
- 技术栈:
- 模块结构:
- 历史文档索引(docs/):
- 历史 PRD 列表:
- 术语表(名称 / 定义):
- 扫描范围与排除(引用 .sopignore):
```

## 使用规则

1. 每次推进阶段:先读 `session.md` 了解进度,结束后更新它。
2. 新增需求:创建 `docs/requirements/<YYYYMMDD>-<需求名>/` 目录,并在 `requirements.md` 追加索引(ID 递增,记录所在目录)。
3. 用户拍板关键决策:立即写入 `decisions.md`。
4. `project-context.md` 仅在 `/sop:init` 或项目结构大变更时更新。
