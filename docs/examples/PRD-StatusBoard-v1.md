# PRD:HTML 状态看板(Status Board)

> 版本:v1.0 | 状态:草稿(待评审)| 作者:SOP Harness | 日期:2026-08-14
> 关联:本项目(.sop/ 规则库),视觉规格见 [PRD-StatusBoard-v1-视觉规格.html](PRD-StatusBoard-v1-视觉规格.html)

## 1. 背景与目标

- **背景**:`/sop:status` 目前只输出纯文本,阶段进度、待确认项、最近决策散落在多个 state 文件中,使用者需要逐个打开文件才能掌握全局;需求整理是多轮会话,缺一个"一眼看清当前到哪了"的入口。
- **目标**:将 `/sop:status` 升级为可视化看板——从"读文本"变为"看面板",一次打开即可掌握当前阶段、六阶段产物状态与待确认项(基线:纯文本 ≤10 行信息 → 目标:看板 1 屏呈现全部状态,打开耗时 ≤1s)。

## 2. 范围

- **In Scope**:读取 `state/` 渲染自包含 HTML 看板;阶段进度可视化;待确认项清单;最近决策展示;产物文件链接;"未初始化"空态引导;刷新按钮。
- **Out of Scope(本次不做)**:Web 服务与实时文件监听(改为手动刷新);多项目聚合;深色模式;权限与登录。
- **非目标(Non-goals)**:不引入任何运行时依赖(保持单文件自包含);不修改 state 文件格式;不做导出/分享。

## 3. 用户角色与用户故事

| 角色 | 描述 | 核心用户故事(As a / I want / So that) |
|---|---|---|
| PM/使用 Harness 的团队成员 | 多轮会话中随时掌握进度 | 作为 PM,我想打开一个看板就看到当前阶段和待确认项,以便快速决定下一步 |
| 评审参与者 | 评审前了解产物状态 | 作为评审人,我想看到各阶段产物是"已完成/缺失/待确认",以便判断能否进入评审 |

## 4. 功能详述

### FR-001 生成并打开状态看板

- **功能说明**:执行 `/sop:status`(或新增 `/sop:vis`)时,在 `docs/` 生成 `sop-status.html` 并提示打开。
- **操作入口**:`.sop/commands.md` 定义的 `/sop:status` 命令;新增别名 `/sop:vis`(可选)。
- **前置条件**:项目已执行过 `/sop:init`(至少存在 `state/session.md` 或 `project-context.md`)。
- **主流程**:1. 读取 `state/requirements.md`、`decisions.md`、`session.md`、`project-context.md` → 2. 解析为看板数据模型 → 3. 按视觉规格模板渲染 `docs/sop-status.html` → 4. 提示用户打开。
- **异常流程**:state 目录或关键文件缺失 → 生成"未初始化"空态页(引导执行 `/sop:init`);单个文件格式解析失败 → 该区块显示"解析失败",其余区块正常渲染,不整体崩溃。
- **业务规则**:看板数据必须与 state 文件一致,生成时重新解析,不使用缓存。

### FR-002 阶段进度与产物状态可视化

- **功能说明**:六阶段(采集/澄清/结构化/评审/门禁/交付)以列表或时间线呈现,每阶段标注状态:未开始 / 进行中 / 已完成 / 阻塞待确认。
- **操作入口**:看板主区。
- **前置条件**:存在 `state/session.md`(含当前阶段)。
- **主流程**:1. 从 session.md 读取当前阶段 → 2. 从 requirements.md 判断各需求所处状态 → 3. 渲染六阶段状态点与当前阶段高亮。
- **异常流程**:session.md 缺失 → 全部阶段显示"未开始"并提示运行 `/sop:req` 或 `/sop:new`。
- **业务规则**:阶段状态色与视觉规格中的状态令牌一致(进行中=品牌蓝、完成=成功绿、阻塞=警告琥珀、错误=危险红)。

### FR-003 待确认项与最近决策展示

- **功能说明**:看板右侧展示待确认清单(来自 session.md 待确认项)与最近决策(来自 decisions.md 前 N 条)。
- **操作入口**:看板侧栏。
- **前置条件**:对应 state 文件存在。
- **主流程**:1. 读取 session.md 待确认项 → 2. 读取 decisions.md 按日期倒序取最近 5 条 → 3. 渲染列表。
- **异常流程**:无待确认项 → 显示"当前无待确认项"空态;decisions.md 缺失 → 该区块隐藏并提示。
- **业务规则**:待确认项支持勾选标记(本地状态,不影响 state 文件;最终确认以 `/sop:clarify` 为准)。

### FR-004 产物文件链接

- **功能说明**:各阶段产物(需求池/澄清记录/PRD/评审记录/门禁报告)以链接形式展示,点击可跳转对应文件。
- **操作入口**:看板各阶段卡片。
- **前置条件**:产物文件存在。
- **主流程**:1. 按命名约定(`docs/PRD-*.md`、`state/*.md`)探测产物 → 2. 生成相对链接。
- **异常流程**:产物缺失 → 显示"未产出"占位,不显示死链。
- **业务规则**:链接使用相对路径,看板文件移动后链接仍有效(同目录或同级)。

## 5. 非功能需求

- 性能:单次生成 ≤1s;看板文件 ≤200KB;浏览器打开即用,无外部请求。
- 安全与合规:无网络请求、不采集数据;生成物仅本地文件。
- 兼容性:Chrome/Edge/Safari/Firefox 最新版;单 HTML 文件,无依赖。
- 可访问性:状态色同时用图标/文字标识(不单靠颜色传达);键盘可操作刷新按钮。

## 7. 验收标准

| 编号 | Given(给定场景) | When(当操作) | Then(则结果) | 优先级 |
|---|---|---|---|---|
| AC-001 | 项目已 init 且 state 完整 | 执行 /sop:status | 生成 docs/sop-status.html,浏览器打开即显示六阶段状态 | P0 |
| AC-002 | state 中 session.md 标注"02 澄清" | 打开看板 | 澄清阶段高亮为"进行中",前后阶段显示"未开始/已完成" | P0 |
| AC-003 | session.md 含 3 条待确认项 | 打开看板 | 侧栏展示 3 条,可勾选 | P0 |
| AC-004 | decisions.md 有记录 | 打开看板 | 展示最近 5 条决策(日期倒序) | P1 |
| AC-005 | state 目录不存在 | 执行 /sop:status | 生成"未初始化"空态页,引导执行 /sop:init,不报错崩溃 | P0 |
| AC-006 | 产物文件缺失 | 打开看板 | 对应阶段显示"未产出"占位,无死链 | P1 |
| AC-007 | 视觉规格检查 | 检查生成 HTML | 所有颜色引用设计令牌(:root 变量),无硬编码色值 | P0 |
| AC-008 | 断网环境 | 打开看板 | 页面完整渲染,无任何外部请求失败 | P0 |
