# 需求整理 SOP 文档库

> 用途:定义"把原始需求整理成可交付需求文档"全流程中,**每个阶段该做什么、不该做什么、产出什么、怎么算过关**。
> 版本:v0.1(初版)| 维护:产品团队 | 更新:2026-08-14
> 用法:① 产品经理逐阶段对照执行;② 作为 AI 需求工作流(Harness)的规则知识库,按阶段加载对应规则文件。

## 阶段总览

```
01 需求采集 → 02 需求澄清 → 03 文档结构化 → 04 多方评审 → 05 质量门禁 → 06 交付集成
   (收集原始诉求)   (消除歧义补缺口)   (产出结构化 PRD)   (多角色找漏洞)   (达到放行阈值)   (进入研发链路)
```

| 阶段 | 一句话目标 | 关键产出 | 过关标准(门禁) |
|---|---|---|---|
| 01 采集 | 完整捕获业务意图与用户诉求 | 需求池(可追溯) | 每条需求有来源、有背景、无遗漏类别 |
| 02 澄清 | 消除歧义,显性化隐性决策 | 澄清记录 + MoSCoW 分级 | 无模糊词、非目标明确、假设已记录 |
| 03 结构化 | 产出可测试的结构化 PRD | PRD 全章节文档 | 功能编号化、每条有验收标准 |
| 04 评审 | 多角色视角审查找漏洞 | 评审记录 + 问题闭环 | P0/P1 问题清零 |
| 05 门禁 | 达到可交付质量阈值 | 门禁检查报告 + 需求基线 | 零歧义测试通过、指标可测量 |
| 06 交付 | 进入研发链路并持续维护 | 需求-任务-用例映射 | 文档与实现同步、变更可控 |

## 文件清单

- `README.md` — 本索引
- `01-需求采集.md` — 采集阶段 DO / DON'T / 产出 / 门禁
- `02-需求澄清.md` — 澄清阶段 DO / DON'T / 产出 / 门禁
- `03-文档结构化.md` — PRD 撰写阶段 DO / DON'T / 产出 / 门禁
- `04-多方评审.md` — 评审阶段 DO / DON'T / 产出 / 门禁
- `05-质量门禁.md` — 放行检查 DO / DON'T / 产出 / 门禁
- `06-交付集成.md` — 交付与维护阶段 DO / DON'T / 产出 / 门禁
- `附录A-通用反模式清单.md` — 跨阶段高频错误速查(待补充)

## 每个阶段文件的统一结构

每份阶段文档按以下固定模板编写,方便机器解析与人阅读:

```markdown
## 阶段目标
## 输入(前置条件)
## ✅ 该做什么(DO)
## ⛔ 不该做什么(DON'T)
## 产出物
## 质量门禁(Exit Criteria)
## 常见反模式举例
```
